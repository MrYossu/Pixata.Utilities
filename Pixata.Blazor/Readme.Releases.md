# Pixata.Blazor releases

What changed in each version of [Pixata.Blazor](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.md), newest first.

>**Version 5.38.0** lets `PixataScheduler` scroll to a time other than the start of the working day. The new `ScrollTime` parameter is used in place of the view's `WorkDayStart` when the day, multi-day, week or timeline view is shown, and is scrolled to again when it changes, so a page can set it to the first appointment's time. The new `ScrollToTime()` method scrolls there once, from code. See [scrolling to a time](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Scheduler.md#scrolling-to-a-time) (#189)

>**Version 5.37.0** lets you choose how long a notification stays, and take one away from code, as Telerik's `NotificationModel.CloseAfter` and `TelerikNotification.Hide()` did. `NotificationHelper.Send()` takes an optional `closeAfter`, which overrides the usual time for the notification's type (`TimeSpan.Zero` keeps it until it's dismissed), and returns the `Notification` it sent. The new `NotificationHelper.Remove()` takes that notification, or its `Id`, and fades it out of every area showing it. See [how long they stay](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Notifications.md#how-long-they-stay) (#200)

>**Version 5.36.1** fixes `PixataEditor` in iframe mode (the default) for an app that imports `pixata.css` rather than linking it, such as into a cascade layer so its own rules win (`@import url(".../pixata.css") layer(pixata);`). The editor copies its content styles into the iframe from the page's stylesheets, but it didn't look inside an `@import`, so none of them reached the iframe: the text had no padding, and an empty editor had a scrollbar. It now follows imports, keeping an import's media query. See [edit modes](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Editor.md#edit-modes) (#202)

>**Version 5.36.0** lets `ApiResponseView` load its data again once the page is interactive, rather than using the data persisted while the page was prerendered, which it has done since 5.26.0...
>- The new `PersistState` parameter, and `ApiResponseViewConfig.PersistState` for every view, turn persisting off (both are `true` by default, so nothing changes unless you set them). Persisting doesn't suit a view whose `LoadApiResponse` also sets up the page (such as setting a form's model), as it isn't called again, or one whose data doesn't survive a round trip through JSON, such as entities with `[JsonIgnore]` properties. See [what persisting the data means for your loader](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.ApiResponseView.md#what-persisting-the-data-means-for-your-loader) (#192)
>- In Blazor Server, the persisted data goes back up to the server in the message that starts the circuit, so a page with more than SignalR's `MaximumReceiveMessageSize` (32KB by default) of data never became interactive. Turn persisting off for views with a lot of data, or set `ApiResponseViewConfig.MaxPersistedBytes`, and a view whose data is bigger than that loads it again instead, and logs a warning. `PersistentStateHelper<T>` has `MaxPersistedBytes` too, and a constructor that takes a logger. See [large data in Blazor Server](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.ApiResponseView.md#large-data-in-blazor-server) (#191)

>**Version 5.35.0** makes two of `PixataGrid`'s parts easier to move across from Telerik...
>- `PixataGridSearchBox` has a `Class` parameter, for its outer element, and adds any other attributes (such as an `id`) to it as well, so a page can style or find it, such as with `FocusOnNavigate Selector=".focus input"`. An empty `Fields` list now searches every text column, as no list does and as Telerik's search box did. It used to search nothing, so a page that bound `Fields` to a list it never filled had a search box that did nothing. See [search box](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#search-box) (#195)
>- The `PixataGridFilterTemplateContext` given to a `FilterMenuTemplate` or `FilterCellTemplate` has the column's `FieldType`, `Title` and `Format`, so one template can be shared by columns of different types, and choose its inputs to suit, as Telerik's `MemberType` allowed. The type is there for a column with no filter yet, and for a nested field. See [custom filters](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#custom-filters) (#188)

>**Version 5.34.0** fixes and improves virtual scrolling in `PixataGrid`...
>- Leaving a page with a virtual grid (`ScrollMode="PixataGridScrollMode.Virtual"` or `ColumnVirtualization="true"`) no longer logs "There is no tracked object with id ..." in the browser. The grid's scroll listener and resize observer were never removed, and the resize observer fires as the grid leaves the page, after the grid had gone. They are now removed when the grid is disposed (#199)
>- Rows scrolled into view before the grid has rendered them, such as when the user drags the scrollbar a long way, now show a grey bar in each cell, as the rows loading with `OnRead` already did, rather than being blank until they arrive. This shows most in Blazor Server. The new `ShowPlaceholders` parameter (`true` by default) turns the bars off for both, leaving those rows blank. See [virtual scrolling](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#virtual-scrolling) (#197)

>**Version 5.33.0** fixes three things in the date pickers and the numeric text box...
>- A date picker (or date range picker) whose page removes it while handling the date just picked, such as a page that shows "Loading..." in place of its filters while it reloads, no longer ends the circuit with an `ObjectDisposedException`. Closing the popup and moving the focus back to the input are now skipped once the picker has gone from the page, in `PixataDatePicker`, `PixataDateRangePicker`, `PixataDateInput` and `PixataCalendar`. See [reloading when the date changes](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.DatePicker.md#reloading-when-the-date-changes) (#193)
>- In WebAssembly (and so in Auto render mode), a date picked from `PixataDateRangePicker`'s calendar now shows in its input straight away. The input used to keep the old date until something else changed, as the reply to the input losing the focus to the calendar reached the browser after the new date, and put the old one back. Each state the input is sent is now numbered, and an older one is ignored. `PixataDatePicker` had the same problem. See [date range picker](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.DatePicker.md#date-range-picker) (#196)
>- Tabbing into a `PixataNumericTextBox` with a `Format` selects the whole number, so typing replaces it. Swapping `£60.00` for `60` when the box got the focus threw the selection away, so typing `12.34` gave `6012.34`, and in Blazor Server the swap arrived a round trip later, by when the user might already have selected the text with the mouse. The swap is now done in the browser the moment the box gets the focus, keeping the selection, and in Blazor Server keys typed quickly are no longer lost to a render that was overtaken by the next key. The new `SelectOnFocus` parameter, as in Telerik's numeric text box, selects the whole number however the box gets the focus, a click included. See [numeric text box](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.NumericTextBox.md#basic-use) (#203)

>**Version 5.32.1** references `Microsoft.AspNetCore.WebUtilities` 10.0.15 (8.0.34 for .NET 8), as 10.0.0 and 8.0.22 have a known high severity vulnerability ([GHSA-x33c-w48q-qrgc](https://github.com/advisories/GHSA-x33c-w48q-qrgc), CVE-2026-114149, a denial of service). An app that references Pixata.Blazor no longer gets NuGet warning NU1903, and no longer has to reference the patched version itself. Its other dependencies have no known vulnerabilities. No code changes (#190, #198)

>**Version 5.32.0** adds `Satisfies`, a FluentValidation rule to use in place of `Must` and `Custom`. In a published (Release) Blazor WebAssembly app, just constructing a validator that uses `Must` or `Custom` stops the .NET runtime with a Mono assertion (`loader.c:1826`), leaving the form's page stuck on its loading indicator, though it works perfectly in a Debug build. `Satisfies` does the same job as `Must`, with the same overloads and default message, and works. See the [validation documentation](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Validation.md)
>- The package now references FluentValidation 12.2.0 directly

>**Version 5.31.1** puts `.25rem` of padding under the calendar's last row of days (or months, years or decades), as there is at the sides, so it no longer touches the bottom edge of the date picker's popup or the calendar's border. See [styling the date pickers](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.DatePicker.md#styling) (#178)

>**Version 5.31.0** fixes two things in the grid's filter menus...
>- A `CheckBoxList` filter menu is now as wide as its longest value, up to the new `--pixata-grid-filter-menu-max-width` (22rem), and a longer value wraps, with its checkbox beside the first line. The list used to scroll sideways for a value longer than about 25 characters, taking the checkboxes out of sight. The search box above the list now fills the menu. The other filter menus are still 232px wide. See [filtering](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#filtering) (#176)
>- A filter menu that doesn't fit above or below its column (in a short window, with the grid part way down) no longer runs off the bottom of the window, taking the Filter and Clear buttons with it. It opens on the side with more room, as tall as the room there, and a `CheckBoxList`'s list gets shorter so the search box and the buttons stay in view. Other menus, and the column menu, scroll. The grid's drop-down lists are limited in the same way. See [filtering](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#filtering) (#177)

>**Version 5.30.0** adds two things to the grid's columns...
>- A column without a `Width` can no longer be squeezed to nothing when the other columns' widths fill the grid. The grid now scrolls sideways once such a column would be narrower than its new `MinWidth`, or the grid's new `ColumnMinWidth` if it hasn't got one. **Behaviour change:** `ColumnMinWidth` defaults to "5rem", so a grid whose columns without a width were narrower than that now scrolls sideways rather than squeezing them. Set `ColumnMinWidth="@null"` for the old behaviour. See [column widths and long titles](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#column-widths-and-long-titles) (#175)
>- The new `WrapHeaders` parameter lets the header titles go onto more lines rather than being cut short with an ellipsis. The filter and column menu buttons now go beside the last line of the title (which, for a title on one line, is where they were), so they stay level along the header when some titles wrap, including when an app wraps them in its own CSS. See [column widths and long titles](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#column-widths-and-long-titles) (#179)

>**Version 5.29.1** fixes grouping by a column that isn't shown (`Visible="false"`). The group rows, the group panel's chip and an export's `Groups` showed the field's name and raw value (such as "CategoryName: Tools"), and ignored the column's `GroupHeaderTemplate`. They now use the hidden column's title, format and template, as they do for one that's shown. See [grouping and aggregates](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#grouping-and-aggregates) (#168)

>**Version 5.29.0** fixes three things in the messages that `MessageView` and `ApiResponseView` show...
>- **Behaviour change:** `MessageView` now shows its message as text, rather than rendering it as HTML. Messages often quote something a user typed, so a company called "Smith & Sons" upset the markup, and a name such as `<img src=x onerror=alert(1)>` ran script in every browser that showed the message. Set the new `MessageIsHtml="true"` for a message that has markup on purpose. `ApiResponseView` does the same with the messages it shows, and has a `MessageIsHtml` parameter too, whose default comes from the new `ApiResponseViewConfig.MessageIsHtml`, so `ApiResponseViewConfig.MessageIsHtml = true` in `Program.cs` brings back the old behaviour for every view. See [MessageView](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Containers.md#messageview) (#165)
>- `ApiResponseView.Notify()` in `MessageView` mode now shows the message in the colour for its type, so `Notify(NotificationType.Success, "Saved")` is green rather than a red error. `MessageView` has a new `Type` parameter for this, with yellow for a warning, blue for information and grey for a general message, set by the new `--pixata-alert-warning-*`, `--pixata-alert-info-*` and `--pixata-alert-secondary-*` variables. See [doing something with the data](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.ApiResponseView.md#doing-something-with-the-data) (#166)
>- The default `ApiResponseViewConfig.Failure` fragment puts a space between any two hyphens in a row in the message it writes into an HTML comment, so a message that contains `-->` no longer ends the comment and has the rest of it rendered as HTML (#167)

>**Version 5.28.0** adds `PixataTooltip`, which shows a small panel next to an element when the pointer is over it, it has the keyboard focus, or it's tapped on a touch screen, or on a click. The target is its child content, or every element that a CSS selector matches (including ones added later), and it can show the target's title, some text, or a template given the target's id, title and `data-` attributes. It goes on the side of the target you ask for, or the opposite side if there isn't room there, and it's kept inside the window. See [the tooltip documentation](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Tooltip.md) (#152)

>**Version 5.27.0** adds two things to the grid...
>- Cells copied from a spreadsheet such as Excel can be pasted into a grid with `EditMode="InCell"` and `Navigable="true"`. The values fill the cells to the right and below, converted to each field's type, and each row that changes raises `OnUpdate`. The new `OnPaste` event lets you check, change or cancel them first, and `PasteFromSpreadsheets="false"` turns it off. See [pasting from a spreadsheet](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#pasting-from-a-spreadsheet) (#151)
>- The export settings are now given the grid's aggregates (in each column's new `Aggregates`) and its grouping (in `Groups`), in `OnBeforeExport` and in a new `Write` overload that formats can override. Pixata.Blazor.Grid.Excel 1.1.0 uses them to write totals, and a heading and totals for each group. See [export](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#export) (#150)

>**Version 5.26.0** fixes six things and adds two styling variables...
>- `ApiResponseView` (and `PersistentStateHelper<T>`) now persists the data loaded while prerendering for a page that goes on to run on the server, not just one that runs in WebAssembly, so in a Blazor Server app the data is no longer loaded twice. Each view also now persists its own data. They used to share one helper, so only the last view's data was kept, and a view without a `Key` could be handed another's data. Views that share a key now load their data again rather than risk that. See [prerendering](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.ApiResponseView.md#prerendering) (#146)
>- `ApiResponseView` in `Notifications` mode no longer shows each message once for every view on the page. Its notification area is now a fallback, which only shows messages when there's no other area (such as one in your layout), and then only in the first view's. `NotificationArea` has a new `Fallback` parameter for this. See [using them for API errors](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Notifications.md#using-them-for-api-errors) (#147)
>- `AuditViewer`'s date filters now work on PostgreSQL when its `TimeZone` is UTC. The dates were passed on with a `Kind` of `Unspecified`, which Npgsql refuses to compare with a `timestamp with time zone` column, and are now marked as UTC. This needs Pixata.AspNetCore 2.4.0 on the server as well (#143)
>- Grid date filters can now be used on PostgreSQL, by passing a `GridQueryOptions` to `ToGridResultAsync()` (in Pixata.AspNetCore 2.4.0), which also converts the dates from the user's time zone if you want. See [dates with a time](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#dates-with-a-time) (#144)
>- Buttons no longer fill an SVG icon that sets its own `fill`, such as `fill="none"` on an icon drawn with lines (as Lucide's and Feather's are), so those icons are no longer drawn as solid blobs. This includes the package's own line-drawn icons in `PixataButton`, such as the refresh and delete icons. See [icons in buttons](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Styling.md#icons-in-buttons) (#148)
>- The components inside a `<fieldset disabled>` now look and behave as if each had `Enabled="false"`. Their clear, drop-down and spin buttons no longer work, the drop-downs don't open from the keyboard, and the editor can't be typed in. See [read-only forms with a disabled fieldset](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Styling.md#read-only-forms-with-a-disabled-fieldset) (#149)
>- The new `--pixata-blazor-input-height` variable (with `-sm` and `-lg` versions) gives every kind of input the same height, with the text centred and the form labels lined up. It isn't set by default, so nothing changes unless you set it. See [one height for every input](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Styling.md#one-height-for-every-input) (#153)
>- The new `--pixata-grid-cell-padding-y` and `--pixata-grid-cell-padding-x` variables set the padding in the grid's cells, for a compact grid without changing its font size. The defaults are as before. See [styling the grid](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Grid.md#styling) (#155)

The grid's button styles applied to every button on the page, and now only apply to the grid's own buttons, which have the new `pixata-blazor-grid-button` class. A plain button of your own in a grid template that should look like the grid's needs that class too. >- The alert, confirm and prompt dialogs from `PixataDialogFactory` are now at most `30rem` wide, so a long message wraps rather than stretching across the screen. Set the new `--pixata-blazor-dialog-predefined-max-width` variable to change it. >**Version 5.24.0** adds `PixataFiles`, with `SaveFile()`, which has the browser save a file that your app has made (a PDF of an invoice, say), and `PrintHtml()`, which prints an HTML document from a hidden frame without leaving the page. >**Version 5.23.0** adds bar charts to `PixataChart`. A `PixataChartSeries` with `Type="PixataChartSeriesType.Bar"` draws horizontal bars, with the categories down the left (the first at the top) and the values along the bottom. Bars take everything columns do, including stacked and 100% stacked bars, data labels, tooltips, `OnSeriesClick` and legend toggling, and a chart with bar series shows only those. With more categories than fit, the bars thin down to 4 pixels and then the chart grows taller, so a bar for each day of a year stays readable. Long category labels are shortened, with the full text shown on hover. See the [charts documentation](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Charts.md#bars) (#134)

>**Version 5.22.0** lets `PixataCheckBox` be posted with a form. >**Version 5.18.1** fixes two things in `AuditViewer`...
>- When the user left the page the viewer was on, it reloaded for the page that was going away, as Blazor tells components about a new location before it disposes the old page. With a scoped `DbContext`, that could clash with the new page's own queries. It now ignores locations on other pages. If loading fails, the viewer now shows the error rather than letting it end a Blazor Server circuit (#111)
>- The "View history" buttons kept their text colour on hover only if the host's stylesheet didn't colour links on hover, so the text could vanish into the button. They now keep `--pixata-primary-color` whatever the host does with links (#112)

>**Version 5.18.0** adds `PixataNumericTextBox`, a text box for numbers with optional spin buttons, `Min`, `Max`, `Step`, `Decimals` and a display `Format`, which has the same parameters as Telerik's NumericTextBox. It works with `int`, `long`, `short`, `decimal`, `double`, `float` and their nullable versions, inside an `EditForm` or on its own. See the [numeric text box documentation](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.NumericTextBox.md) (#113)

## Styling changes in v5.5.0

These only affect you if you wrote CSS of your own for the notifications, or relied on their default look. See [Notifications](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Notifications.md#icons-and-colours) for the details.

- **Notification classes.** The classes inside the notification area now start with `pixata-blazor-notification`, so your own styles for classes such as `message` or `icon` no longer land on the notifications. `notifications-area` is now `pixata-blazor-notification-area`, `notification` is `pixata-blazor-notification`, and `new`, `remove`, `icon`, `message` and `dismiss` are `pixata-blazor-notification-` followed by the old name. Their styles have moved from the component's scoped CSS into pixata.css.
- **Notification icons.** The default icons are now built-in SVG ones, so you don't need Font Awesome for them. Call `NotificationHelper.UseFontAwesomeIcons()` in `Program.cs` if you want Font Awesome's icons back. `NotificationHelper.GetIconClass()` now returns `""` for a type that shows the built-in icon, and the new `GetDisplayIcon()` gives you what to pass to `PixataIcon` to show the same icon as the notifications.
- **Notification colours.** The background was always white. It now comes from `--pixata-notification-bg`, which defaults to `--pixata-blazor-surface-bg`, and the text from `--pixata-notification-color` (which defaults to `--pixata-blazor-text-color`) rather than the page's text colour. The corners are now rounded (`--pixata-notification-border-radius`).
- **Close buttons.** The cross on a `pixata-btn-close` button was always black. It's now drawn in the colour of the text around it, or in `--pixata-close-button-color` if you set that.

## Styling changes in v5.4.0

These only affect you if you wrote CSS of your own for these components, or relied on their default look.

- **Audit viewer classes.** The viewer's styles have moved from a `<style>` block inside the component into pixata.css, and every class now starts with `pixata-blazor-audit-`, followed by the old name without any `audit-` it started with. So `view-btn` is now `pixata-blazor-audit-view-btn`, and `audit-timeline` is now `pixata-blazor-audit-timeline`. The old names were global, so they could clash with your own CSS, and the block's rules (for `.filters`, `.spinner`, `.user` and so on) applied to the rest of your page while the viewer was on it. The colours now come from the `--pixata-*` variables, so the viewer follows your theme, and it uses your page's font rather than the system font. See [styling the audit viewer](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.AuditViewer.md#styling).
- **`Confirm` and `Inform` ids.** The `confirmOverlay`, `confirmOverlayContent`, `informOverlay` and `informOverlayContent` ids are now the classes `pixata-blazor-confirm-overlay`, `pixata-blazor-confirm-content`, `pixata-blazor-inform-overlay` and `pixata-blazor-inform-content`, so you can have more than one on a page. The pop-up has a softer shadow and smaller corners, and both can be changed with variables. See [Containers](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Containers.md#styling-confirm-and-inform).
- **Notification icons.** The default icons are now Font Awesome's solid (`fas`) ones, which are in the free set, rather than the regular (`far`) ones, most of which are Pro only. The icon colours now come from CSS variables, so `NotificationHelper.GetIcon()` is obsolete. See [Notifications](https://github.com/MrYossu/Pixata.Utilities/blob/master/Pixata.Blazor/Readme.Notifications.md#icons-and-colours).
